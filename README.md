# Customer Review MCP Assistant

Учебно-портфолио проект: Telegram-ассистент для малого бизнеса, который помогает работать с отзывами клиентов через MCP-style архитектуру.

## Описание

Проект состоит из двух независимых частей:

1. **MCP Server** — HTTP-сервер с инструментами (tools) для работы с отзывами в SQLite.
2. **Telegram Bot** — бот, который принимает обычный текст от пользователя, через LLM выбирает нужный инструмент и вызывает MCP-сервер.

## Зачем MCP-style архитектура

В уроке по MCP показан паттерн разделения ответственности:

- **Сервер** знает только про данные и бизнес-логику (отзывы, статистика, черновики).
- **Бот** знает только про интерфейс с пользователем и маршрутизацию запросов.
- **LLM** решает, какой инструмент вызвать, но не имеет прямого доступа к базе данных.
- Сервер публикует описания инструментов и **JSON Schema** их входных аргументов через `/tools` и сам **проверяет по этим схемам** каждый вызов `/call_tool` до запуска инструмента.
- Telegram-бот **не загружает** схемы из `/tools`: LLM-маршрутизатор хранит список разрешённых инструментов и их описания для промпта отдельно (`VALID_TOOLS` и `SYSTEM_PROMPT` в `telegram_bot/llm_router.py`). Это осознанное упрощение для учебного проекта; тест следит, чтобы список инструментов не разъезжался с сервером. Даже если LLM вернёт неверные аргументы, их отклонит сервер.

Это упрощённая учебная реализация без полноценного MCP SDK: HTTP endpoints `/tools` и `/call_tool` имитируют поведение MCP для понимания идеи.

## MCP Tools

| Инструмент | Описание |
|------------|----------|
| `list_reviews` | Последние отзывы |
| `find_reviews` | Поиск по тексту или имени клиента |
| `find_reviews_by_rating` | Отзывы с конкретной оценкой |
| `find_negative_reviews` | Негативные отзывы (оценка 1–2) |
| `add_review` | Добавить новый отзыв |
| `get_review_stats` | Статистика по отзывам |
| `draft_reply` | Черновик ответа (rule-based) |
| `calculate` | Безопасный калькулятор |

Ограничения аргументов (проверяются сервером): `limit` — целое число от 1 до 50 (по умолчанию 10), `rating` — целое число от 1 до 5, `review_id` — целое число от 1 до 2^63 − 1 (9223372036854775807, максимум INTEGER в SQLite). Неизвестные аргументы отклоняются.

## Установка

Требуется **Python 3.10+** (в коде используются аннотации вида `dict | None`). Проверьте версию: `python --version`.

```powershell
# Клонировать репозиторий и перейти в папку проекта
cd customer-review-mcp-assistant

# Создать виртуальное окружение в корне проекта
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

# Скопировать и заполнить переменные окружения
copy .env.example .env
```

На Linux/macOS вместо `Activate.ps1` используйте: `source .venv/bin/activate`

Заполните в `.env`:

- `TELEGRAM_BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather)
- `OPENAI_API_KEY` — ключ OpenAI API
- `OPENAI_MODEL` — модель для маршрутизации запросов, по умолчанию `gpt-4o-mini` (нужна модель, поддерживающая Chat Completions с `response_format={"type": "json_object"}` и `temperature=0`)
- `MCP_SERVER_URL` — адрес MCP-сервера, по умолчанию `http://127.0.0.1:8008`

Версии зависимостей: в `requirements.txt` заданы только те границы, что защищают совместимость (`aiogram` 3.x, `fastapi` < 1, `pydantic` 2.x, `openai` от 1.55.3 до 2.x); остальные пакеты не закреплены. Проверено с Python 3.12.10, aiogram 3.28.2, fastapi 0.136.3, pydantic 2.13.4, openai 2.40.0 (маршрутизатор дополнительно проверен с openai 1.55.3 и 1.109.1), requests 2.34.2.

## API MCP Server (учебный)

### GET /tools

Возвращает MCP-style описания всех инструментов: `name`, `description` и `inputSchema` (JSON Schema входных аргументов). Эти же схемы сервер применяет при вызове инструментов. Поддерживается только тот минимум JSON Schema, который нужен проекту: `type` (`string`/`integer`), `required`, `additionalProperties: false`, `minimum`/`maximum`.

### POST /call_tool

```json
{
  "tool": "list_reviews",
  "arguments": {"limit": 5}
}
```

Ответ при успехе:

```json
{
  "ok": true,
  "tool": "list_reviews",
  "result": [...]
}
```

`arguments` можно не передавать — это то же, что `{}` (`null` трактуется так же). Если поле передано, оно должно быть JSON-объектом: список, строка, число или булево значение не отклоняются на уровне HTTP (это не 422), а получают обычный ответ с `ok: false`.

Ответ при ошибке (неизвестный инструмент, аргументы не соответствуют схеме — в том числе `arguments` не объект, — или ожидаемая ошибка самого инструмента, например «отзыв не найден») — HTTP 200 с `ok: false`; инструмент при неверных аргументах не запускается:

```json
{
  "ok": false,
  "error": "Аргумент «limit» должен быть не меньше 1"
}
```

Клиенту показывается текст только ожидаемых ошибок инструментов (в коде — семейство `ToolError`). Любое другое исключение, включая обычный `ValueError`, считается внутренней ошибкой: клиент получает общее `{"ok": false, "error": "Внутренняя ошибка инструмента"}`, а подробности остаются только в логе сервера.

Бот различает два случая: недоступный сервер (нет соединения, таймаут, HTTP-ошибка) или ответ неверного формата (не JSON-объект, нет булева `ok`, при `ok: true` нет `tool`, `tool` не совпадает с вызванным или нет `result`, при `ok: false` нет текста ошибки) — пользователю советуют проверить, что MCP-сервер запущен; и корректный `ok: false` — пользователю показывается текст ошибки инструмента.

## Тесты

Тесты работают офлайн: Telegram и OpenAI не вызываются (сетевые обращения в тестах блокируются), база данных — временный файл, а не `mcp_server/reviews.db`.

```powershell
pip install -r requirements-dev.txt
python -m pytest -q
```

## Известные ограничения

- Поиск `find_reviews` использует SQL `LIKE`: символы `%` и `_` в запросе работают как шаблоны, а регистронезависимость SQLite действует только для латиницы — кириллический запрос `доставк` не найдёт `Доставка`.
- Отзывы выводятся в одном сообщении Telegram; при большом `limit` или длинных текстах сообщение может превысить лимит Telegram в 4096 символов (разбиение на части не реализовано).
- Проверка аргументов выполняется в Python; ограничений `CHECK` в схеме SQLite нет.
- Запросы к OpenAI и MCP-серверу синхронные и блокируют обработчик бота на время вызова.

## Статус проекта

Проект реализован как учебный MVP:
- MCP-style сервер запускается локально через FastAPI;
- SQLite-база создаётся автоматически и заполняется тестовыми отзывами;
- Telegram-бот подключается к серверу через HTTP;
- LLM используется для выбора подходящего инструмента;
- реальные ключи хранятся в `.env` и не добавляются в репозиторий.
